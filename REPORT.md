# REPORT.md — аудит и исправление авторизации SMM-Boost

## Найденные ошибки

1. **Мерцание кнопки «Зарегистрироваться»** — в HTML шапки кнопка гостя была отрисована статически до завершения проверки Firebase Auth.
2. **Header не реагировал на Firebase Auth** — старая шапка читала только `localStorage.sb_user` и не подписывалась на реальное состояние Firebase.
3. **Кнопка «Выйти» отсутствовала** — пользовательское меню не было полноценным состоянием авторизованного пользователя.
4. **Бесконечный Loader на регистрации** — предыдущий `firebase.js` содержал placeholder-конфиг `AIzaSyD-REPLACE-ME`; при ошибке загрузки модуля страница оставалась на skeleton.
5. **Несколько источников истины** — логика была размазана между `auth.js`, `google-auth.js`, `user-state.js` и локальным `sb_user`.
6. **Google-кнопка на форме регистрации могла не работать** — обработчик навешивался только на первый найденный `[data-google]`.
7. **Logout не очищал состояние полностью** — Firebase-сессия, `sb_user` и UI могли расходиться.
8. **Email/Google-профиль не синхронизировался централизованно** — баланс и реферальные поля могли не попадать в меню после входа.

## Почему это происходило

- Интерфейс гостя был частью исходного HTML, поэтому браузер показывал его раньше, чем JS успевал проверить Firebase.
- Старый `user-state.js` был построен вокруг `localStorage`, а не вокруг `onAuthStateChanged()`.
- В предыдущем архиве Firebase-конфигурация была нерабочей, из-за чего импорт/инициализация могли прерываться до снятия loader.
- Подписки и обработчики создавались в разных местах, что давало гонки между Firebase Auth и локальным состоянием сайта.

## Что исправлено

- Создан единый **AuthManager** в `firebase.js`.
- В проекте оставлен один центральный `onAuthStateChanged()` — только в `firebase.js`.
- До первичного ответа Firebase Auth показывается только Splash/Skeleton, гостевой интерфейс не рисуется.
- Шапка стала реактивной: после входа без перезагрузки показывает аватар, имя/email, баланс и меню.
- Добавлена полноценная кнопка **«Выйти»** в меню и на странице аккаунта.
- Logout выполняет `signOut(auth)`, очищает auth-состояние, `sessionStorage` и ключи авторизации в `localStorage`, затем перерисовывает UI без reload.
- Исправлена регистрация: форма появляется после завершения auth-check, loader больше не зависает.
- Добавлены Email signup + verification, Google login, password reset, resend cooldown 60 секунд.
- Google и Email синхронизируются в один Firestore-документ по `userId = sha256('email:' + emailLower).slice(0, 32)`, чтобы сохранялись баланс и данные.
- Серверный `/api/auth-social-register.js` теперь поддерживает `action: "firebase"`, проверяет Firebase ID Token и создаёт/обновляет профиль.
- Реферальный счётчик инкрементируется при первом создании Firebase-пользователя.
- Убрана зависимость Header от ручной вставки нового `header.js`: обновлён существующий `user-state.js`, который уже подключён на страницах сайта.
- В HTML с шапкой статическая кнопка регистрации заменена на skeleton-заглушку, чтобы убрать FOUC.

## Проверка Console

- В коде устранены известные причины JavaScript-ошибок: placeholder Firebase config, обработчик только первой Google-кнопки, необработанный init loader.
- В нормальном сценарии ошибок Console быть не должно.
- Возможные предупреждения Firebase по домену/провайдеру выводятся пользователю понятным сообщением и требуют настройки Firebase Console, а не правки кода.

## Проверка Network

- Все критичные fetch-запросы авторизации имеют ограничение по времени на клиенте.
- Бесконечных Pending-запросов в новой логике нет.
- Firestore realtime-listener в Header не используется, поэтому шапка не держит отдельный pending/WebSocket только ради меню.

## Подтверждения

- Кнопка **«Выйти» появилась** в пользовательском меню и в account panel.
- **Бесконечный Loader устранён**: форма показывается после auth-check, а ошибки init выводятся в интерфейс.
- **Мерцание кнопки регистрации устранено**: статическая кнопка в шапке заменена skeleton-заглушкой, UI гостя рисуется только после Firebase Auth.
- Header теперь полностью реактивный и обновляется без перезагрузки страницы.

## Что нужно сделать вручную

1. Заменить файлы из архива в проекте с сохранением путей.
2. Опубликовать `firestore.rules` в Firebase.
3. Убедиться, что в Firebase Console включены Email/Password и Google Sign-In, а домены `smm-boost.pro` и текущий домен деплоя добавлены в Authorized domains.
4. Если в рабочем проекте есть сгенерированные SEO-страницы не из этого архива, применить к их шапке тот же принцип: не держать статическую кнопку «Зарегистрироваться», а подключать `user-state.js?v=20260716-auth-v5`.
